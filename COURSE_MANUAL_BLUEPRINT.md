# 🏗️ Course Manual System: The Blueprint

This blueprint documents the complete architecture and setup of the Course Manual System. It is designed to act as a **step-by-step guide for replicating this system** for any future course.

## 🌟 Core Technologies
1. **MyST Markdown**: The foundational text format. It extends standard Markdown with scientific features, directives (admonitions, dropdowns), and executable code cells.
2. **Jupyter Book (via MyST CLI)**: Compiles the MyST Markdown files into a beautiful, static HTML website.
3. **Thebe**: Enables in-browser interactive code execution without requiring a backend server.
4. **Sveltia CMS (Decap CMS fork)**: A lightweight, Git-based Content Management System for non-technical instructors to edit content directly on the live website.
5. **GitHub Actions**: Automates the build and deployment of the site to GitHub Pages.

## 📂 Project Structure
A standard course manual uses the following directory structure:

```text
├── _static/                # Static assets (images, CSS) copied directly to the build
│   └── images/             # CMS uploads all images here
├── admin/                  # Sveltia CMS configuration and custom widgets
│   ├── config.yml          # Auto-generated CMS schema
│   ├── custom-widgets.js   # Custom CMS blocks (Python code, Alerts)
│   └── index.html          # The CMS application entry point
├── content/                # Course material organized by module
│   ├── 00_Course_Overview/
│   ├── 01_Module_Name/
│   │   ├── 01_lecture_notes.md
│   │   ├── 02_examples.md
│   │   ├── 03_lab_assignment.md
│   │   ├── 04_resources.md
│   │   └── code/           # Jupyter notebooks (.ipynb) and Python scripts
├── scripts/                # Python automation scripts
├── myst.yml                # Master configuration for the MyST site
└── package.json / requirements.txt # Project dependencies
```

## 🚀 Step 1: Setting up MyST and Interactive Code

The `myst.yml` file is the heart of the site configuration.

### Key Configurations in `myst.yml`
* **Interactive Code (Thebe)**: 
  To make Python code cells runnable in the browser, ensure these settings exist:
  ```yaml
  project:
    jupyter: true
    thebe: true
    thebe_config:
      kernel_name: python3
  site:
    head:
      - tag: script
        attributes:
          type: text/x-thebe-config
        value: '{"useBinder": false, "useJupyterLite": true}'
    options:
      launch_buttons:
        thebe: true
  ```
* **Static Assets**:
  To ensure the CMS and images are published, define static folders:
  ```yaml
  project:
    static_files:
      - admin
      - _static
  ```

## 🛠️ Step 2: Setting up the CMS (Sveltia)

The CMS allows instructors to edit content without touching Git.

1. **`admin/index.html`**:
   Load Sveltia CMS and your custom widgets.
   ```html
   <script src="https://unpkg.com/@sveltia/cms/dist/sveltia-cms.js"></script>
   <script src="custom-widgets.js"></script>
   ```

2. **`admin/custom-widgets.js`**:
   Sveltia's default Markdown editor can corrupt complex MyST syntax. We bypass this by creating **Custom Insert Widgets**.
   * We created a `python-code` block that generates MyST code cells: ` ```{code-cell} python3 `
   * We created an `admonition` block that generates MyST alerts: ` ::::{note} `
   * *Critical*: The widgets use simple `text` inputs (not `markdown`) to ensure Immutable.js compatibility and prevent Sveltia from formatting the output.

3. **`admin/config.yml` (Generated by Python)**:
   This file tells the CMS which folders to manage. 
   * *Critical Settings for Images*: Images must be stored in a directory that MyST copies verbatim (`_static`), and the `public_folder` must be the absolute path to your GitHub Pages URL.
   ```yaml
   media_folder: "_static/images"
   public_folder: "/<YOUR-REPO-NAME>/_static/images"
   ```

## 🤖 Step 3: Automation Scripts

We built three Python scripts to eliminate manual setup:

1. **`scripts/scaffold_modules.py`**:
   Run this once when starting a new course. It creates the `content/` folder structure, generating the 14 standard modules with the 4 standard markdown files (`01_lecture_notes.md`, etc.).
2. **`scripts/auto_build_menu.py`**:
   Scans the `content/` folder and dynamically updates the `toc` (Table of Contents) in `myst.yml`. Run this whenever you add or rename a module folder.
3. **`scripts/update_cms_config.py`**:
   Scans the `content/` folder and generates `admin/config.yml`. It automatically creates a CMS "Collection" for every module folder so it appears in the Sveltia dashboard. Run this whenever you add a new module.

## ☁️ Step 4: GitHub Actions Deployment

The site is hosted for free on GitHub Pages. We use a GitHub Actions workflow (`.github/workflows/deploy-pages.yml`) to automatically build the site every time a commit is pushed (either via Git or via the Sveltia CMS save button).

```yaml
# deploy-pages.yml (abbreviated)
steps:
  - name: Install MyST
    run: python -m pip install --upgrade pip mystmd
  - name: Build site
    env:
      BASE_URL: /${{ github.event.repository.name }}
    run: myst build --html
  - name: Upload artifact
    uses: actions/upload-pages-artifact@v3
    with:
      path: ./_build/html
```

## 📝 Checklist for Replicating this Setup

To clone this exact architecture for a *new* course (e.g., "MIS 204: Data Science"):

1. Create a new GitHub Repository and enable GitHub Pages (deploying via GitHub Actions).
2. Copy the `.github/`, `admin/`, `scripts/`, and `_static/` folders from this repository.
3. Copy `myst.yml`, but change the `project.title` and `author`.
4. Update `scripts/update_cms_config.py` so the `repo` maps to your new repository (e.g., `repo: your-username/MIS-204`) and `public_folder` maps to the new repo name (`/MIS-204/_static/images`).
5. Run `python scripts/scaffold_modules.py` to generate the new folder structure.
6. Run `python scripts/auto_build_menu.py` to update the Table of Contents.
7. Run `python scripts/update_cms_config.py` to build the CMS config.
8. Commit and Push to GitHub. The new course manual and CMS are instantly live!
